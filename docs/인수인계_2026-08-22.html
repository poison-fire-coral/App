실행하기

순서가 중요하다. 특히 3번을 빼먹으면 앱이 로딩만 돈다.

  1. DB와 백엔드를 띄운다. PostgreSQL 17이 로컬 5432에 있어야 한다. 시드를 안 돌리면 레벨 테이블이 비어 레벨업이 영원히 안 일어난다. 
    # App/ 에서
npm run db:seed
npm run dev   # 5001
  2. 기기를 PC 백엔드에 연결한다. 기기를 다시 꽂을 때마다 초기화되므로 연결이 안 되면 이것부터 의심한다. 
    adb reverse tcp:5001 tcp:5001
  3. dart-define을 반드시 넣는다. 빼면 에뮬레이터 주소(10.0.2.2)로 붙어서 실기기에서는 타임아웃까지 아무 반응이 없다. 
    flutter run \
  --dart-define=API_BASE_URL=http://localhost:5001/api/v1
  4. 개발자 모드를 켠다. 앱 우상단 설정 → 개발자 모드 스위치. 켜야 GUEST 로그인 버튼과 퀘스트 화면의 순간이동 도구가 나타난다.
카카오 로그인은 아직 콜백이 안 돌아온다. 매니페스트에 kakao{네이티브키}://oauth 인텐트 필터가 없기 때문이다. 그때까지 일상 개발은 GUEST 로그인으로 한다 — 고정 uid dev_local_001이라 계정이 매번 갈리지 않는다.

무엇이 바뀌었나

인증 코어 — 모든 것의 전제

기존 AuthService는 소셜 SDK를 호출하고도 토큰을 버리고 bool만 돌려줬다. 그래서 앱 전체의 로그인 상태가 is_logged_in 불리언 하나였다. 이걸 갈아엎었다.

NEWservices/token_store.dart
NEWservices/api_client.dart
NEWmodels/api_exception.dart
NEWmodels/auth_models.dart
NEWdata/auth_repository.dart
MODservices/auth_service.dart
  • 토큰은 secure storage에. refresh는 14일짜리라 평문 XML에 두면 안 된다. 메모리 캐시로 매 요청 await을 피한다.
  • 모든 호출은 ApiClient를 지난다. {data, error} 봉투를 풀고 Bearer를 주입하고 401이면 갱신 후 한 번만 재시도한다.
  • 리프레시는 단일비행. 홈 진입 시 세 요청이 동시에 401을 맞는데, 세 번 갱신하면 토큰 회전 때문에 서로를 무효화한다.
  • authToken 파라미터를 전부 없앴다. 호출부가 토큰을 알 필요가 없어져 오히려 단순해졌다.

라우팅 — signup을 Navigator에서 상태로 내렸다

"온보딩 1단계에서 뒤로 → 가입 방법 재선택"을 만들려니, 루트 밖 화면(상태 기반)과 스택 화면(Navigator)이 섞여 뒤로가기가 비결정적이 됐다. _AuthPhase를 도입해 로그인 전 화면을 전부 상태로 통일했다.

EXP는 서버가 진실

의뢰서 절대원칙 ①이 "EXP·난이도·배지 판정은 100% 서버 계산"이라고 못박고 있다. 게다가 서버와 클라이언트의 레벨 테이블이 실제로 달랐다. 화면 렌더 코드는 한 줄도 안 고치고 데이터 소스만 갈아끼웠다. 

// exp_service.dart 에 생성자만 추가 — 위젯은 그대로
factory ExpBreakdown.fromServer(Map raw, {bool isAbused})
factory LevelUpResult.fromServer(Map lv, {previousLevel, gainedExp})

로컬 ExpService는 지우지 않았다. 수락 전 "예상 EXP"와 오프라인 폴백으로 남는다.

진행바 — 지점 수 + 접근률

진행바가 0%에서 100%로 점프하던 진짜 원인은 계산식이 아니라 spotCount가 항상 1이었기 때문이다. 서버에는 다중 지점 개념이 없다. 4a가 이미 정확히 재고 있던 접근률을 위로 올려 홈 캐러셀도 쓰게 했다. 

progress = (완료한 지점 + 현재 구간 접근률) / 전체 지점

// 2지점 중 1개 완료 + 다음 지점 30% 접근 = 65%

치명 · 서버 계약

AUTH_NOT_REGISTERED는 401이 아니라 400

CustomError.ts의 (string, string, any) 분기가 statusCode를 건드리지 않아 초기값 400이 그대로 나간다. UNAUTHORIZED, DUPLICATE_NICKNAME도 마찬가지다.

대응 HTTP 상태가 아니라 error.code 문자열로 분기한다. 401 인터셉터는 status == 401 || code == 'UNAUTHORIZED' 둘 다 본다.

치명 · 빌드

dart-define 없이 빌드하면 실기기가 멈춘다

기본값이 10.0.2.2(에뮬레이터 전용)라 실기기에서는 갈 곳이 없다. 오류도 안 나고 20초 타임아웃까지 로딩만 돈다. 한 번 여기에 걸렸다.

대응 --dart-define=API_BASE_URL=http://localhost:5001/api/v1 + adb reverse

치명 · 렌더

비균일 테두리 + borderRadius = 자식이 안 그려진다

NoteBox가 "빛은 위에서 온다"를 테두리 네 면에 다른 색으로 표현했는데, Flutter는 borderRadius가 있는 비균일 테두리를 만나면 paint 단계에서 예외를 던지고 자식을 통째로 그리지 않는다. 앱 전역 11곳에서 글자가 안 보였다.

대응 그늘을 BlurStyle.inner 그림자로 바꿨다. 회귀 방지: test/widgets_paint_test.dart

치명 · 렌더

스크롤뷰 안의 Spacer는 화면을 비운다

SingleChildScrollView는 최대 높이가 무한이라 flex 자식을 놓을 수 없다. 로그인 화면이 통째로 빈 채로 배포될 뻔했다.

대응 LayoutBuilder + minHeight + IntrinsicHeight. 회귀 방지: test/screens_render_test.dart

주의 · 데이터

목업 퀘스트는 서버에 accept·verify를 못 한다

백엔드 Quest.id가 Int라 'q_01' 같은 목업 id는 컨트롤러에서 isNaN으로 걸린다.

대응 호출 전 int.tryParse(quest.id) != null로 거른다. 목업은 표시 전용.

다음에 할 일

먼저  퀘스트 사이클 실기기 검증

코드는 다 됐는데 기기에서 한 번도 안 돌려봤다. 개발자 모드 → 순간이동으로 실내에서 확인 가능하다. 

# 확인할 것
앱이 표시한 EXP  ==  quest_completions.exp_awarded
홈 상단 레벨 링   ==  users.level / users.exp_current

# 같은 requestId 로 두 번 보내도 completions 행은 1개여야 한다

순간이동은 서버를 우회하지 않는다. 위조한 좌표가 그대로 verify로 가서 거리 검증을 정상 통과하므로 EXP·레벨업 로직이 진짜로 돈다.

먼저  카카오 리다이렉트 스킴

AndroidManifest.xml에 인텐트 필터와 AuthCodeCustomTabsActivity를 추가해야 loginWithKakaoTalk 콜백이 돌아온다. 코드는 이미 준비돼 있다.

그다음

  • 지도 카메라 이동 디바운스 — 지금은 이동할 때마다 nearby가 나간다. 300ms 디바운스가 필요하다.
  • GET /quests/my로 진행중 목록 동기화 — API는 이미 붙여뒀는데 기동 시 대조를 아직 안 한다.
  • 사진 S3 업로드 — /quests/:id/upload-url presign은 있다. AWS 키 유효성부터 확인할 것.
  • 시드 퀘스트 유형 다양화 — 21개가 전부 VISIT이다. 주석은 퀴즈형·탐색형으로 나눠놨는데 questType을 안 넣었다.
  • 배지 서버 API (S4) — 모델만 있고 API가 없다. 지금은 로컬 카운터로만 표시한다.

개발자 모드 제거

실제 제출 전에 걷어낸다. 순간이동이 남아 있으면 누구나 EXP를 무한으로 벌 수 있어 앱의 핵심인 위치 인증이 무효가 된다. 나중에 고고학이 되지 않도록 한 곳에 몰아뒀다.

  1. lib/dev/ 디렉터리를 통째로 삭제한다.
  2. 호출부를 찾아 그 블록만 지운다. 예상 3~4곳 
    grep -rn "DEV-ONLY" lib/
  3. flutter analyze로 남은 미사용 import를 정리한다.

이번에 의도적으로 하지 않은 것들. 나중에 "왜 없지?" 싶을 때 참고.

  • 퀴즈형·수집형 제출 — 서버 verify가 위치 인증만 처리한다. quizAnswer 제출 경로가 없어 방문형만 완성했다.
  • 지도 뷰포트 조회 — GET /quests bounds 방식은 S2 항목이나, 현재 nearby로 동작하므로 유지했다.
  • 약관 문서 — 체크박스 UI는 제거했고 서버에는 termsVersion: '2026-08-implicit-v1'을 보낸다. implicit이라는 단어가 "묵시적 동의 구간"임을 DB에 남긴다. 실제 약관이 생기면 체크박스만 되살리면 된다.
  • Firebase — main.dart의 초기화는 google-services 플러그인 미적용으로 항상 실패하지만, 실제로 쓰이는 곳이 없어 그대로 뒀다. 콘솔에 실패 로그가 찍히는 건 정상이다.
  • iOS — 의뢰서상 MVP는 Android만이다.

실기기 검증 스크린샷 14장은 docs/screenshots/2026-08-22-s1-검증/에 있다. 버그 3건은 전·후를 짝으로 남겼다. 같은 폴더의 README.md가 각 장이 무엇을 증명하는지 설명한다.
