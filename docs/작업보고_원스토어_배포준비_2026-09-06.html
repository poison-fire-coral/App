A-4. 수집형(사진 N장) 인증 — 7종 중 마지막

빈 칸을 먼저 보여줍니다

"3장 필요"라고 글로만 쓰면 몇 장을 더 찍어야 하는지 매번 세어야 합니다. 목표 장수만큼 칸을 깔면 남은 수가 그대로 보이고, 다음에 채울 칸만 테두리가 진합니다. 잘못 찍은 장은 지울 수 있습니다 — 못 빼면 목표를 채우고도 다시 할 수 없습니다.

업로드는 한 장씩 순서대로. 동시에 던지면 실패했을 때 몇 장이 올라갔는지 알 수 없고, 현장 네트워크에서는 병렬이 오히려 느립니다. "2 / 3 올리는 중"을 보여줍니다.

사진이 인증 조건인 유형에서는 '사진 없이 완료'를 감춥니다 — 서버가 장수를 세어 거절하므로(PHOTO_COUNT_NOT_MET) 열어 두면 눌러 놓고 400을 맞습니다.

자동 생성 비율표를 여러 갈래로 바꿔 관광지·축제·시장에 수집형을 10~15%씩 넣었습니다. 어느 장소에서도 방문형이 과반입니다. 실내 전시(문화시설)는 돌아다니며 여러 장을 찍기 어려워 넣지 않았습니다.

A-5. 잡히지 않던 오류와 오프라인 상태

전 — 세 가지가 동시에 잘못돼 있었습니다

잡히지 않은 예외를 받는 곳이 한 군데도 없었습니다. 릴리스에서 빌드 도중 예외가 나면 회색 오류 상자가 그대로 보였고, 비동기 콜백에서 터진 것은 아무 데도 남지 않았습니다.

네트워크가 끊기면 로그아웃됐습니다. 콜드 스타트가 모든 ApiException을 하나로 묶어 토큰을 지웠습니다. 지하철에서 앱을 켜기만 해도 세션이 날아가고, 저장해 둔 대기 인증까지 지워졌습니다.

내부 호스트 이름이 사용자에게 보였습니다. SocketException: Failed host lookup: 'xxx.ngrok-free.dev'가 토스트에 그대로.

후

runZonedGuarded(async) · FlutterError.onError(위젯 트리) · PlatformDispatcher.onError(나머지) 셋을 모두 겁니다. 도착지는 _reportCrash 한 곳이라 크래시 리포팅 SDK를 붙일 때 호출부를 찾아다닐 필요가 없습니다.

연결 실패와 세션 만료를 구분합니다. 연결이 안 된 것은 세션에 대해 아무것도 말해 주지 않으므로 토큰을 두고 저장된 프로필로 이어 가되, 화면 위에 한 줄로 알리고 '다시 시도'를 줍니다.

지도도 마찬가지 — "이 동네에 퀘스트가 없다"와 "못 불러왔다"는 사용자가 할 수 있는 일이 다릅니다. 연결 문제일 때만 안내를 띄우고 눌러서 재조회합니다.

A-8. 안드로이드 릴리스 빌드

전 — 세 가지가 릴리스를 막고 있었습니다

카카오 로그인 콜백 스킴이 없었습니다. kakao{키}://oauth는 앱이 매니페스트에 직접 선언해야 하는데(SDK 쪽에는 intent-filter가 아예 없음) 없었습니다. 안드로이드에서 카카오 로그인이 동작한 적이 없습니다.

Firebase Gradle 플러그인이 적용돼 있지 않았습니다. google-services.json은 있는데 읽는 쪽이 없어 리소스가 생성되지 않았고, Firebase.initializeApp()의 예외를 try/catch가 삼켜 푸시가 조용히 죽어 있었습니다.

릴리스가 디버그 키로 서명되고, 평문 통신을 허용하고 있었습니다.

후 — 릴리스 APK가 R8을 통과하고 병합 매니페스트가 의도대로 나옵니다

  • 카카오 스킴 kakaobddd999…://oauth 생성 확인. 키는 앱과 같은 dart_defines.json에서 Gradle이 읽습니다 — 두 곳에 적으면 갈라집니다
  • processGoogleServices가 google_app_id 생성 확인. 백그라운드 핸들러(@pragma('vm:entry-point') — 없으면 릴리스에서 트리셰이킹됩니다), 알림 아이콘·색·채널 추가
  • key.properties가 있으면 그 키로, 없으면 디버그 키 + 빌드 경고
  • 평문 통신은 개발용 매니페스트로 이동. 릴리스에 없는 것 확인
  • 앱 이름 local_quest → 로컬 퀘스트, namespace com.example → com.team
  • R8 축소 + 유지 규칙, Android 12+ 시스템 스플래시, allowBackup=false
  • API_BASE_URL 없이는 릴리스가 동작하지 않게 — 값이 없으면 개발자의 ngrok 터널로 떨어졌고, 그 터널이 죽으면 스토어의 앱 전부가 서버를 잃습니다

A-10. 실기기 재검토에서 나온 것 2026-09-06

지적 1 — 검색창 안에 또 블록이 있었다

앱 테마가 모든 입력칸에 filled: true(오목한 면)와 사방 테두리를 줍니다. 폼에서는 맞지만 지도 검색은 이미 흰 알약 위에 얹혀 있어서, 알약 안이 또 다른 면으로 꽉 찼습니다. 포커스가 들어오면 굵은 빨간 테두리까지 겹쳤습니다.

border만 none으로 둬서는 안 됩니다 — enabledBorder·focusedBorder는 테마 값이 그대로 남습니다. 셋 다 껐습니다.

지적 2 — 안내 문구가 필터 칩을 덮고 있었다

"이 범위에는 퀘스트가 없어요"를 Positioned(top: 84)로 따로 띄워서 칩 줄 위에 그대로 얹혔습니다 — 전체·골목·산책이 반쯤 가려졌습니다.

검색창·칩과 같은 세로 흐름에 넣어 겹칠 수 없게 만들었습니다. 칩 높이나 검색창 높이가 바뀌어도 다시 어긋나지 않습니다. 모양도 바꿨습니다 — 폭을 꽉 채우던 반투명 상자에서 내용만큼만 차지하는 불투명 알약으로. 지도 라벨 위에 반투명을 겹치면 글자끼리 섞여 둘 다 안 읽힙니다.

지적 3 — 방향 표시가 현위치와 따로 놀았다

점에서 14px 떨어진 곳에서 시작하는 삼각형이라, 지도 위에 종이비행기 하나가 별도로 떠 있는 것처럼 보였습니다 — 현위치 마커와 다른 물건으로 읽혔습니다.

꼭짓점을 현위치 한가운데로 옮기고, 멀어질수록 옅어지는 부채꼴로 바꿨습니다. 점이 꼭짓점을 덮어 둘이 한 덩어리가 됩니다. 지도(3a)와 진행 화면(4a) 둘 다 확인했습니다.

덤 — 마이그레이션 베이스라인이 실제로 필요했다는 증거

재검토 첫 시도에서 로그인이 통째로 실패했습니다. 원인은 The column (not available) does not exist — 스키마에 추가한 marketing_agreed·photo_urls가 로컬 개발 DB에 없었기 때문입니다.

이건 고장이 아니라 예고된 상황이고, 계획 P2-1(마이그레이션 베이스라인 재작성)이 다루는 바로 그 문제입니다. 추가 컬럼 3개를 적용하고 베이스라인을 "적용됨"으로 표시해 해결했습니다(prisma migrate status → Database schema is up to date). 운영 DB는 처음부터 베이스라인으로 만들어지므로 이 단계가 필요 없습니다.

실기기에서 확인하지 못한 것

  • 수집형(사진 N장) 인증 화면 — 해당 퀘스트가 수원화성 시드에만 있는데, 지도 조회가 개발용 좌표 고정을 보지 않아 거기까지 못 갔습니다(아래 참고). 레이아웃은 자동 테스트에서 3가지 크기 + 큰 글자까지 통과합니다.
  • 카카오·구글 로그인 — SHA-1 등록과 키 해시가 아직 없어 지금은 불가능합니다. 당신 몫 6번을 끝낸 뒤가 첫 확인 시점입니다.
  • 사진 업로드 — S3 자격이 개발 환경에 없습니다.

재검토에서 새로 눈에 띈 것 (배포를 막지는 않음)

  • 지도 화면이 개발용 좌표 고정을 보지 않습니다. 홈과 진행 화면은 보는데 지도만 실제 GPS를 씁니다. 개발 도구끼리의 불일치라 사용자에게는 영향이 없지만, 시드 퀘스트를 실기기로 확인할 길이 막힙니다.
  • 서버에서 수락한 퀘스트가 앱에 안 뜹니다. 홈 캐러셀은 기기에 저장된 목록만 보고, 서버가 내려주는 activeQuests를 쓰지 않습니다. 기기를 바꾸면 진행 중이던 퀘스트가 사라진다는 뜻이기도 합니다.

B 일부러 미룬 것

할 수 있었지만 하지 않았습니다. 각각 이유가 있습니다.

B-1. 개발자 모드 제거 당신 지시

lib/dev/를 그대로 뒀습니다. 좌표 순간이동이 실내에서 GPS를 흉내 내는 유일한 수단이라, 지우면 지도 작업과 이후 실기기 검증을 할 방법이 사라집니다.

출시 안전성에는 영향이 없습니다. devToolsEnabled가 bool.fromEnvironment('DEV_TOOLS', defaultValue: kDebugMode)라 릴리스 빌드에 아무것도 넘기지 않으면 false로 굳고 AOT가 통째로 트리셰이킹합니다. 서버의 GUEST 분기도 NODE_ENV=production으로 막혀 있습니다. → 제출 전에 릴리스 APK에 개발용 버튼이 없는지 눈으로 확인하면 됩니다.

B-2. 탐색형 퀘스트 2건의 정답 채워야 함

시드의 "벽화의 연도"와 "폐선로의 끝"은 quizAnswer가 비어 있습니다. 정답이 현장 실물이라 제가 지어내면 실제로 다녀온 사람이 틀립니다. prisma/seed.ts에 TODO를 달아 뒀고, 세 줄(quizQuestion, quizOptions, quizAnswer)만 채우면 바로 채점됩니다.

자동 생성에서는 퀴즈·탐색형을 만들지 않습니다 — 같은 이유입니다.

B-3. 재동의 화면

AuthRepository.needsReconsent()는 있지만 화면이 없습니다. 첫 출시라 대상자가 개발용 계정뿐이고, 실사용자가 생긴 뒤 문서를 고칠 때 필요해집니다. 지금 만들면 검증할 대상이 없습니다.

B-4. 크래시 리포팅 SDK

전역 핸들러는 붙였고 도착지를 _reportCrash 한 곳으로 모아 뒀습니다. Crashlytics를 붙이려면 Firebase 콘솔 설정이 필요해 코드만으로 끝나지 않습니다. 붙일 때 그 함수 한 줄만 늘리면 됩니다.

B-5. 강제 업데이트 게이트

버전 확인 엔드포인트와 차단 화면. 첫 출시에는 막을 구버전이 없고, 서버 API가 아직 바뀔 수 있어 규칙을 정하기 이릅니다.

B-6. 성능 — PostGIS 전환과 getNearbyQuests

getNearbyQuests는 여전히 전체 테이블을 메모리로 올려 JS에서 Haversine을 계산하고, 요청 경로 안에서 TourAPI를 동기 호출합니다. 지도(뷰포트) 경로는 이미 DB에 bounding box를 넘기고 상한이 있어 실제 최다 호출 경로는 괜찮습니다.

베이스라인에 places(lat, lng) 인덱스가 들어갔으니, 실제 데이터가 쌓인 뒤 측정하고 판단하는 것이 맞습니다. 지금 PostGIS로 옮기면 근거 없이 복잡도만 늘립니다.

C 당신이 직접 해야 하는 것

계정·키·법적 신고·실물 확인. 순서대로 하시면 됩니다.

  1. 위치기반서비스사업 신고 리드타임 있음 · 먼저
    위치정보법 제9조. 스토어와 무관한 국내 법적 의무입니다. 처리에 시간이 걸리니 지금 바로 걸어두고 나머지를 병행하세요. 개인·소상공인은 완화된 절차가 있습니다.
    정부24 「위치기반서비스사업 신고」 · 전자민원센터 emsit.go.kr · 소상공인 특례 lbsc.kr
  2. 약관 3종 검토·확정
    초안은 src/routes/legal.router.ts에 있습니다. 반드시 고칠 것:
    · CONTACT_EMAIL — 지금 support@localquest.example (실제로 없는 주소)
    · PROVIDER_NAME — 상호 또는 본인 이름
    · EFFECTIVE_DATE — 실제 서비스 개시일
    법적 책임은 확정하시는 쪽에 남습니다.
  3. 서버 호스팅 — Northflank 계정 생성 및 배포
    무료 Sandbox(2 서비스 · DB 1 · always-on, 슬립 없음). 이 앱은 10분마다 도는 인프로세스 크론이 있어 슬립하면 안 됩니다.
    · Docker 서비스 + Postgres 생성 → 저장소 연결(Dockerfile 자동 인식)
    · 환경변수: DATABASE_URL JWT_SECRET NODE_ENV=production KAKAO_REST_API_KEY TOUR_API_SERVICE_KEY AWS_* CORS_ORIGINS ADMIN_USER_IDS
    · 헬스체크 경로를 /health로 지정
    여기서 나온 HTTPS 도메인이 4·5·8번에 전부 쓰입니다.
  4. 기존 로컬 개발 DB에 베이스라인 표시
    마이그레이션 히스토리를 다시 잡았습니다. 로컬 DB에는 이미 테이블이 있으므로 실행하지 말고 표시만 하세요:
    npx prisma migrate resolve --applied 20260906000000_baseline
    자세한 내용과 검증 방법은 prisma/migrations/README.md에 적어 뒀습니다.
  5. 릴리스 키스토어 생성 분실 = 업데이트 불가
    keytool -genkey -v -keystore localquest-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias localquest
    android/key.properties.example를 key.properties로 복사해 채우세요.
    원스토어에는 구글 플레이의 관리형 키 같은 것이 없습니다. 이 키를 잃으면 앱을 영영 업데이트할 수 없습니다 — 파일과 비밀번호를 서로 다른 두 곳에 오프라인 보관하세요.
  6. Firebase · 카카오 콘솔에 지문 등록 이게 없으면 로그인 안 됨
    keytool -list -v -keystore localquest-release.jks -alias localquest로 SHA-1을 얻은 뒤:
    · Firebase → 프로젝트 설정 → Android 앱 → SHA-1 추가(릴리스 + 디버그 둘 다) → google-services.json 다시 받아 android/app/에 교체. 지금 파일은 oauth_client: []라 구글 로그인이 동작한 적이 없습니다
    · 카카오 개발자 → 내 애플리케이션 → 플랫폼 → Android → 키 해시 등록
    · 카카오 JavaScript 키의 사이트 도메인에 http://localhost 확인 (지도 WebView가 이 오리진을 보고합니다)
  7. 원스토어 개발자센터 가입
    개인개발자로 가입 가능(본인인증 필요, 등록비 없음). 구글 플레이와 달리 테스터 12명 × 14일 요건이 없습니다.
  8. 스토어 등록물 준비
    · 스크린샷 재촬영 — docs/screenshots/는 8월 개발 캡처입니다
    · 앱 이름 · 짧은 설명 · 상세 설명(한국어)
    · 연령등급: IARC 인증 ID가 없으므로 원스토어 설문으로 신규 취득 + 비게임 앱은 한국 서비스용 연령등급을 별도 설정해야 합니다. EXP·레벨·배지가 있지만 게임물이 아닌 위치기반 생활 앱으로 등록 시 확인하세요
    · 개인정보처리방침 URL: {도메인}/privacy
    · 계정 삭제 안내 URL: {도메인}/account/delete
    · 앱 아이콘은 이미 완성돼 있습니다(adaptive icon + 5개 밀도)
  9. 심사용 테스트 계정 없으면 심사자가 앱을 못 봄
    로그인이 카카오·구글뿐이라 심사자가 들어올 수 없습니다. 심사 전용 카카오 계정을 만들어 자격을 제출하세요. 서버에 심사용 백도어를 만들지 않은 이유는, 그 구멍이 심사가 끝난 뒤에도 남기 때문입니다.
