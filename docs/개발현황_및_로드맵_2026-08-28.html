程

남은 길

로컬 퀘스트 · 현재 개발 현황과 출시까지의 로드맵

기준 와이어프레임 v2 (1a–6d) · 개발 순서 및 작업 의뢰서
조사 대상 App/ — Flutter 45파일 11,561줄 / Express·Prisma 28파일 · 커밋 8339bc8 · 2026-08-28

골격은 다 서 있다. 의뢰서의 S1~S4에 해당하는 화면 20개와 API 17개가 실제로 붙어 있고, 실기기에서 로그인부터 배지까지 한 바퀴가 돈다. 남은 것은 “처음부터 만들기”가 아니라 이미 만든 것을 스펙에 맞추는 일이다.

빠진 것은 네 덩어리다. ① 지도가 뷰포트로 조회하지 않는다 — 서버에는 bounds·클러스터 조회가 구현돼 있는데 앱이 반경 API를 부른다. 의뢰서 절대원칙 ③이 지켜지지 않는 상태다. ② 사진이 서버에 올라가지 않는다 — S3 presign이 서버에 있는데 앱이 호출하지 않는다. ③ EXP 배율 5개 중 3개가 상수로 박혀 있다 — 신규지역은 항상 참, 비피크는 항상 거짓, 스트릭은 영원히 0이다. ④ 법적·보안 요건이 비어 있다 — 약관 화면이 없는데 동의로 기록되고, GUEST 로그인이 토큰 검증 없이 열려 있다.

아래 로드맵은 5개 마일스톤 · 19 영업일이다. 순서는 위험도 순이지 화면 순이 아니다. R1은 지금 제출하면 사고가 나는 것들이고, R2–R4가 스펙 이행, R5가 출시 준비다.

P1 스펙 미달 — 의뢰서·와이어프레임과 다른 동작

지도가 반경으로 조회한다 절대원칙 ③ 위반

의뢰서는 “반경 개념 없음, 항상 뷰포트(bounds) 기준”이라고 못 박았다. 서버에는 bounds 조회와 geohash 클러스터링이 이미 구현돼 있는데, 앱은 /quests/nearby를 부른다. 그래서 지도를 옮겨도 새 영역의 퀘스트가 안 뜨고, 줌아웃해도 클러스터가 생기지 않는다. 여기 하나가 3a·3d 두 화면을 동시에 막고 있다.

lib/screens/map_screen.dart:242–247 ↔ src/services/quest.service.ts:285

찍은 사진이 서버로 가지 않는다

4b에서 촬영·갤러리 선택은 되지만 업로드 호출이 없다. photoUrl은 항상 비어서 verify로 넘어가고, DB photo_url은 계속 null이다. 공개/비공개 선택 UI도 의미가 없는 상태다.

lib/screens/quest_verify_screen.dart — /quests/:id/upload-url 호출부 부재

EXP 배율 5개 중 3개가 상수다

스펙은 “24h 후 1일 1회 ×0.3”인데, 구현은 이전 완료가 있으면 QUEST_ALREADY_DONE 409로 전면 차단한다. 재수행 배율이 코드에 들어갈 자리가 없다.

P2 출시 품질

CI가 없다 · 마커 생성기가 테스트에 섞여 있다

.github/가 없어 PR마다 검증되는 것이 없다. 전체 테스트를 돌릴 때마다 PNG 108장이 다시 구워진다 — 결과는 같지만 테스트가 에셋을 쓰는 구조다.

공간 인덱스가 없다

PostGIS 대신 @@index([lat, lng]) B-tree 하나다. 뷰포트 조회가 최다 호출이 될 텐데, 시드 21개라 아직 문제가 드러나지 않았을 뿐이다.

오프라인·약전파 재시도 큐가 없다

멱등 requestId는 준비돼 있어 재시도해도 안전하지만, 실패한 인증을 보관했다가 다시 보내는 큐 자체가 없다. 산 위에서 전파가 끊기면 그 완료는 사라진다.

회원 탈퇴 경로가 없다

와이어프레임 5d에 있고 스토어 심사에서도 요구된다. 서버에 탈퇴 엔드포인트가 없다.

콘텐츠가 21개다

의뢰서가 “가장 큰 리스크”로 지목한 항목. 시드 21개로는 지도를 옮겼을 때 빈 화면이 대부분이다. 관광공사 API 동기화가 이를 일부 메우고 있지만, 퀘스트 텍스트는 사람이 써야 한다.

1

GUEST 프로바이더를 운영 환경에서 차단

auth.service.ts:44의 GUEST 분기를 NODE_ENV !== 'production'일 때만 타도록 감싼다. 지우지 말 것 — 개발·테스트가 이 계정에 의존한다.

DoD 운영 빌드에 provider:"GUEST"로 요청하면 403, 개발 서버에서는 통과

2

개발자 도구를 컴파일 타임 플래그로 감싼다

삭제보다 const bool kDevTools = bool.fromEnvironment('DEV_TOOLS') 게이트가 낫다. false면 Dart 컴파일러가 lib/dev/ 참조를 통째로 트리셰이킹한다. 로그인 화면의 개발용 계정 버튼, 설정의 DEV-ONLY 블록이 같은 플래그를 본다.

DoD flutter build apk --release 산출물에서 개발자 진입점이 보이지 않고, --dart-define=DEV_TOOLS=true로는 그대로 동작
